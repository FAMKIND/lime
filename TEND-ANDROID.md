1. **Heading and Quote are jam-post only.** In core's `Block` docs: "Heading … Jam posts only; in a chat the line stays text", the same for Quote, Indent, Divider, Freewall, Button and Image, and iOS's chat strip (`FormattingToolbar.swift`) is **B, I, U, S, Link, Code, Bulleted, Numbered, and Indent/Outdent inside a list**; Quote, headings and the rest are behind `model.isPost`. A heading typed in a chat would arrive as literal `# …` text on every receiver. The engine and LIME-405's strip therefore follow iOS: no Heading, no Quote.
2. **"http upgraded as iOS 188o did" is the jam button rule, not the chat link rule.** iOS's chat `LinkInput.url(from:)` keeps `http://`, gives a bare address `https://`, gives `me@x.com` `mailto:`, and lets the core decide (http, https, mailto). `LinkInput.https(from:)` (the upgrade) is for jam buttons. The engine twins `url(from:)` (its test `testLinkInputIsCheckedByTheCore`, including the refused list).
3. **iOS keeps list markers as characters of the text** ("• ", "2. " with a `limeMarker` attribute) and needs `cleanUpAfterEdit`, `markerRange`, `anchor/location` and `renumber` to keep them whole. The brief's own suggested shape (text, runs, line kinds) has no marker in the text, so the engine uses it: **each line has a kind (paragraph, bullet, number, code), a level 0 to 2 and a start number; the marker is computed (`composer_markers`) with the core's `list_markers`**. A half-cut marker cannot exist, so the iOS tests that are about that (`ComposerDeletionTests`: "a selection that starts/ends inside a marker leaves no half marker", "selecting just the marker removes it") have no twin: the property holds by construction (the selection tests that remain meaningful are twinned).
4. The brief names `enter(doc, at)`, `from_markdown`, `to_markdown`, `plain_text`: all exist; iOS's `autoStart`/`undoAutoStart` (the "- " typed at a line start) and `handleMarkerDelete` (Backspace at an item's start) are in too, because a rich composer without them is not iOS's.
**Pure logic (moved to core) vs glue (stays):** moved: `toggle`/`allCharacters` (inline styles), `setLink`, `LinkInput.url`, `state` and `typingAttributes` (what the strip shows pressed, the style to type with), `toggleList` + `renumber` (now `composer_markers`), `toggleCode`, `handleReturn`, `shiftLevel`/`shiftedLevels`, `autoStart`/`undoAutoStart`, `handleMarkerDelete`, and the document to and from Markdown (`blocks(from:)`, `spans(in:)`, `attributed(from:)`). **Stays in Swift:** the `NSAttributedString` attribute keys, `restyle` and the fonts, `UITextView` delegate wiring and undo, mentions, pictures (`insertImage`, `FFFC`), and every jam-post paragraph style (`limePara`: headings, quote, indent, button, divider, freewall), `cleanUpAfterEdit` (not needed).
**Built:** NEW `core/src/client/composer_rules.rs` (one registration line in `client.rs`; no other core file edited; `Cargo.toml` untouched). **The document value:** `ComposerDoc { text, runs: [ComposerRun { start, end, style: ComposerStyle, link }], lines: [ComposerLine { kind, level, start }] }`, all offsets **UTF-16 code units**, one line record per `\n`-separated line, runs covering the text and merged. **Functions** (each takes and returns values): `composer_empty`, `composer_from_markdown`, `composer_to_markdown` (= `serialize` of the blocks; `to_markdown(from_markdown(x)) == normalise_message_markdown(x)` is tested over 18 inputs), `composer_plain_text`, `composer_markers`, `composer_replace(doc, start, end, text, style) -> ComposerEdit` (typing, a delete, a paste with newlines), `composer_enter`, `composer_backspace` (the list rule at an item's start, else None), `composer_toggle_style` (`ComposerStyleKind`), `composer_set_link` (refuses an address `allowed_link` refuses), `composer_link_url`, `composer_style_at`, `composer_toggle_list`, `composer_toggle_code`, `composer_shift_list`, `composer_auto_start` / `composer_undo_auto_start` (`ComposerAutoStart`, `ComposerAutoResult`), `composer_format_state` (`ComposerFormatState`: the pressed states, `in_list`, `can_indent`, `can_outdent`). Exported types: `ComposerStyle`, `ComposerStyleKind`, `ComposerRun`, `ComposerLineKind`, `ComposerLine`, `ComposerDoc`, `ComposerEdit`, `ComposerFormatState`, `ComposerAutoStart`, `ComposerAutoResult`. **Name check (rule 2):** each was grepped as a whole word (camel and snake case) in `ios/Lime`, `android/app/src/main`, `core/src`, `~/Sites/lime/ios/Lime` and `~/Sites/lime/core/src`: no clash (Swift has `ComposerDocument`, `FormattingState`, `InlineFormat`, `BlockKind`, none of the exported names).

## LIME-405 — the rich-text composer UI (Android night 3, after)
